# ResolveDesk 项目介绍

面向英文零售客服的 Qwen3 Agent 原型，支持订单查询、退货、换货、缺货回退、补邮箱和转人工。使用 FastAPI、SQLite、本地 Ollama 及独立适配器评测；客户、订单、支付与交易均为合成模拟数据。

## 个人实现

- 构建有状态工具流程，加入参数与引用校验、澄清记忆、库存检查、独立客户确认、原子事务和幂等回执。
- 将首次原始预测与后续修复、追问尝试与实际送达、提案与交易提交分别记录，保留全部失败。
- 对已有 Qwen3-4B 适配器做实际 LoRA 续训：最新 V8 完成 1,344 次更新，rank 8、112 个 FP32 张量、3,670,016 个参数；从 96 个源场景的 1,100 条去重样本中实际采样 888 条。
- 设计三臂对照，分别观察固定旧权重的流程变化、固定 V8 流程的训练组合变化，并整理六组 PNG/SVG、逐案例 CSV、双语报告和失败分析。

## 最新结果：共同40场景的阶段性分析

原三臂评测在固定截止时间结束，保存 **48/48/40，共136/144条完整记录**。7个任务未启动，1个任务存在已发出、返回状态不明的调用，不得自动重放。缺失8条不计成功或失败，原144条评测仍未完成。

用户另行授权后，仅对三组共同完成的前40场景做回顾性对照：**120条轨迹、657次模型调用**，没有补跑或新增训练。

| 指标 | 旧权重/V7 | 旧权重/V8 | 保存V8权重/V8 |
| --- | ---: | ---: | ---: |
| 正确处理业务任务 | 30/40 | 30/40 | 33/40 |
| 可满足换货子集 | 5/10 | 7/10 | 8/10 |
| 缺货回退子集 | 1/2 | 2/2 | 2/2 |
| 必要转人工 | 13/16 | 10/16 | 13/16 |
| 补邮箱子集 | 2/4 | 2/4 | 3/4 |
| 首次七字段全部正确 | 24/40 | 24/40 | 27/40 |
| 无依据的初始授权 YES | 1/32 | 1/32 | 1/32 |
| 相同动作重复次数 | 48 | 15 | 9 |
| 不必要转人工执行 | 5 | 0 | 0 |
| 模型调用数 | 236 | 208 | 213 |

固定 V8 流程时，训练组合对应的正确处理率从 **75.0%到82.5%，增加7.5个百分点**，但有 **5例改善、2例退化，仍有7例失败**。首次付款字段正确数从 **39/40降至37/40**，调用数从208增至213，授权误报仍为1/32。固定旧权重改流程时，整体仍是30/40，5例改善与5例退化抵消。不能把这些结果归因于某一项训练技巧。

“正确处理”包含提出正确方案后客户确认或拒绝；正确拒绝后订单应保持原状。因此换货/回退成功数不等于实际换货或退款次数。初始授权 YES 误报也不等于已发生未授权交易。

## 必须保留的局限

该共同前40来自固定臂块顺序和截止时间，是非随机截断，仅覆盖20/24类。缺少“可用换货明确拒绝退货”“缺货回退缺支付方式”“可用换货缺邮箱”“邮箱与支付双缺失”四个分支，不能声称V8重点修复全部有效。16个必要转人工场景全保留、缺失8个全属非转人工，类别构成已变化，不能外推到原48，或直接与历史实验总体率相比。

这是同作者自编合成场景，不是官方 τ-bench 或真实生产数据。基线此前已微调；CUDA路径是冻结FP16底座上的LoRA，不是NF4 QLoRA。本轮只读使用保存权重，历史1,344步训练与本轮新增0步分开；未切换默认provider或宣称生产可用。

## 独立保留的历史完整实验

较早的CUDA run002在另一组48场景上完成 **96条轨迹、509次调用**：首次七字段正确率64.6%→81.3%，初始无依据YES由12/36降至3/36，但业务正确处理 **46/48→45/48，出现回归**。这不是最新V8结果，也未与共同40样本池化。
